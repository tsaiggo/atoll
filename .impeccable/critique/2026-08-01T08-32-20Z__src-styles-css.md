## Design Specificity Verdict

Atoll's geometry, tide line, carousel, and semantic states feel authored for the product. The material itself is category-interchangeable: it reads as a generic Windows 11 Card because it uses the same light/dark fallback, translucent Card fill, weak tint wash, and inset contour vocabulary. The reference instead behaves like a continuation of black display hardware.

The deterministic scan reported zero rule violations in `src`. That is not evidence of visual equivalence: the problem is an intentional-direction mismatch, not malformed markup or a detector-level anti-pattern.

## Overall Impression

The current shell is tidy and technically safe, but it is solving the wrong material problem. It simulates a softly tinted Fluent widget; the reference simulates an opaque piece of polished black hardware. More blur or more color will move Atoll farther away.

## What's Working

- Exact shell geometry and native region clipping protect the lower corners from the previous rectangular compositor spill.
- Content remains concise, recognizable, and appropriate for a glanceable media surface.
- Theme, reduced-transparency, and forced-colors fallbacks are explicit and robust.

## Priority Issues

### [P1] Wrong material family

**Why it matters:** The reference's premium quality comes from stable near-black mass, not translucent frosted glass. Atoll becomes nearly white in Windows light mode, so it can never feel continuous with a display cutout.

**Fix:** Replace the shell material world with an invariant near-black `Obsidian` surface across Windows themes. Let artwork and small status elements carry color; do not recolor the shell by module.

**Suggested command:** `$impeccable bolder`

### [P1] Native runtime has no real backdrop material

**Why it matters:** `.native-runtime .atoll-shell` disables `backdrop-filter`, so the installed app shows an opaque fallback plus CSS gradients. Calling it Acrylic raises an expectation the runtime does not meet.

**Fix:** Stop presenting translucency as the goal. Use a deliberate opaque optical stack: deep-black base, one restrained specular edge, a soft internal vertical falloff, and a controlled lower ambient-occlusion shadow.

**Suggested command:** `$impeccable polish`

### [P2] Missing optical separation

**Why it matters:** The current shell reserves no external shadow gutter and uses only an inset contour. Against a bright wallpaper it reads as a flat card, while the reference has a strong contact shadow and a crisp black silhouette.

**Fix:** Add a safe, region-aware shadow solution: either reserve a narrow transparent lower gutter and include it in the native region contract, or build the depth inside the silhouette with a bottom absorption gradient and edge highlight. Do not restore rectangular DWM Acrylic.

**Suggested command:** `$impeccable polish`

### [P2] Module tint competes with the hardware illusion

**Why it matters:** Mint, blue, sand, and coral washes make the background feel software-decorated. The reference keeps its surface neutral and lets the album cover provide the only saturated color.

**Fix:** Remove module washes from Reef and Compact. Reserve semantic color for progress, status, and actions. If Expanded needs context, keep any ambient tint below roughly three percent.

**Suggested command:** `$impeccable quieter`

## Persona Red Flags

**Alex (Power User):** Controls and shortcuts are efficient, but the light Card surface makes the persistent overlay visually louder than the compact information warrants.

**Sam (Accessibility-Dependent User):** The existing theme support is robust, but replacing it with fixed black must preserve text contrast, forced-colors behavior, and visible focus states rather than relying on subtle material differences alone.

**Riley (Stress Tester):** Any external-shadow redesign must be tested at 125%, 150%, and 200% scaling because the previous Acrylic compositor ignored the asymmetric lower-corner region.

## Minor Observations

- The reference is visually closer to piano black or smoked glass than Acrylic.
- The physical Mac notch supplies real black continuity and hides the top seam; Windows requires that continuity to be simulated with the edge-attached geometry.
- Merely changing `#f9f9f9` to black will still look flat unless edge light, internal falloff, and shadow are redesigned together.

## Questions to Consider

- Should Atoll prioritize the invariant black hardware illusion over following the Windows light theme?
- Should Expanded remain the same black object, or deliberately transition into a Windows Fluent panel?
- Is the target the exact macOS silhouette, or the same level of optical refinement with an Atoll-specific shape?
